## The go run mechanism: `@<sha>` through the proxy

Chosen: `go run github.com/carlosframework/rastrillo/cmd/dsgen@<sha>`.

Evidence it resolves for an unreleased commit:

- Warm, with the shared module cache:
  `go: downloading github.com/carlosframework/rastrillo v0.19.1-0.20260830174253-c5fd8c9238b2`
  then `dsgen: wrote 369 files` — 0.97s.
- Cold, with `GOMODCACHE` and `GOCACHE` pointed at empty directories and
  `GOPROXY=https://proxy.golang.org,direct`, `GOSUMDB=sum.golang.org`,
  `GOFLAGS=` — i.e. what a fresh CI runner sees: **23.7s**, 369 files.
  The rename redirect (`carlosframework/rastrillo` →
  `rastrilloorg/rastrillo`) and the sumdb both held.
- The proxy path and a local checkout produce the same bytes: `diff -r`
  between `go run ./cmd/dsgen` in the framework worktree at `c5fd8c9`
  and the published `_site/design-system` from the clean export is
  empty.

Why this over "check the framework out at the pinned sha and run
`go run ./cmd/dsgen`": the deploy path in AGENTS.md is a human running
`git archive | tar -x && npm ci && npm run check` in a scratch
directory. The proxy form keeps that a two-command runbook; the checkout
form adds a clone of a second repo, a second sha to keep in step, and a
directory to clean up, in the one place where the steps are typed by
hand under deploy pressure. 24s cold is not a cost worth that.

The checkout form is recorded in AGENTS.md as the fallback if the
redirect is ever undone, the module goes private, or a build has no
network — it takes the same two flags and yields identical output.

## What changed

- **`hack/gen-design-system.mjs`** (new). Reads the sha from
  `src/_data/docsversion.json`, checks `go` is on PATH (with a real
  message if not), runs dsgen into `src/design-system` at mount
  `/design-system`, then counts what landed and writes a
  `.dsgen-source.json` receipt naming the sha, mount and file count.
  No "already generated, skipping" path — it is ~1s warm, and the
  failure this change has to avoid is a build that quietly ships no
  gallery.
- **`hack/sync-docs.mjs`** — the design-system half is gone; the 49
  markdown pages are vendored byte-for-byte exactly as before.
- **`hack/check-docs.mjs`** — the count guard became a structural one
  (below).
- **`eleventy.config.js`** — passthrough and `ignores` verified working
  against a gitignored generated directory (they are: Eleventy's
  gitignore handling narrows template discovery, not explicit
  passthroughs). Added an `eleventy.after` hook stripping `.dsgen` and
  `.dsgen-source.json` from the output: the passthrough **does** copy
  dotfiles — confirmed, 371 files in `_site/design-system` before the
  hook, 369 after — and there is no per-file filter on a mapped
  directory passthrough.
- **`package.json`** — `build` and `serve` run the generator first;
  `check` is `npm run build && …`; new `gen-design-system` script.
- **`.gitignore`** — `src/design-system/`.
- **`src/_data/docsversion.json`** — `ac287b5` → `c5fd8c9`. Forced: the
  dsgen command does not exist at `ac287b5` (`git ls-tree ac287b5 cmd/`
  shows only `cmd/rastrillo`). The re-sync also brought a real prose
  change, `src/docs/templates.md` (+26/-9), which is the framework's own
  edit in that same commit range.

## CI

`.github/workflows/build.yml` gains, between setup-node and `npm ci`:

```yaml
      - uses: actions/setup-go@v5
        with:
          go-version: "1.25"
          cache: false          # no go.mod here to key the built-in cache on

      - id: pin
        run: echo "sha=$(jq -r .sha src/_data/docsversion.json)" >> "$GITHUB_OUTPUT"
      - uses: actions/cache@v4
        with:
          path: |
            ~/.cache/go-build
            ~/go/pkg/mod
          key: dsgen-${{ runner.os }}-${{ steps.pin.outputs.sha }}
```

The cache key is the framework sha because the framework sha is exactly
what decides what gets downloaded and compiled: same pin, same cache.
`jq` rather than `node -p` because `package.json` is `"type": "module"`.

## The guard, and it failing

`hack/check-docs.mjs` now checks, in order: dsgen's `.dsgen` stamp is in
`src/design-system`; the `.dsgen-source.json` receipt's sha equals
`docsversion.json`'s and its mount is `/design-system`; the built file
count equals the generated count equals the receipt's; neither dotfile
was published; `index.html` and `tokens.css` are in the built site; at
least 3 themes, each with a `theme-<name>.css`, each with at least 12
locales including `en`, each locale carrying all ten page kinds
(Overview, Tokens, Components, UI primitives, Shells, the demo, the
modal, and the column/sidebar/topbar shell demos); and the built
`index.html` really carries `/design-system/` links.

Six ways of breaking it, all caught:

## Worth a human's attention

1. **This branch carries a docs content change as well as the build
   change.** Moving the pin to `c5fd8c9` was unavoidable (dsgen does not
   exist at `ac287b5`) and pulled in `src/docs/templates.md` (+26/-9),
   the framework's own edit. Read it as part of review; it is prose the
   site publishes.
2. **The floors in the guard are deliberate constants.** `MIN_THEMES=3`
   and `MIN_LOCALES=12` will fail loudly if the framework legitimately
   drops a theme or a language. That is the intended trade — the
   alternative derives the expectation from the same tree it is checking,
   which cannot catch a half-generated gallery. Changing them is a
   one-line, on-purpose edit, and the message says so.
3. **The 20 MB is gone from the working tree, not from history.** Clones
   of this repo are the same size as before; `git archive` exports are
   20 MB lighter, which is what the deploy path cares about.
4. **The build now needs the network.** An offline `npm run build` fails
   where it used to succeed. It fails loudly, with the dsgen error and a
   line saying the gallery is not generated, so it cannot ship a hole —
   but it is a new dependency for anyone building on a plane.
5. **Nothing is pushed.** No PR, per the repo's PR-only workflow the
   next step is push + open a PR against `main`.
